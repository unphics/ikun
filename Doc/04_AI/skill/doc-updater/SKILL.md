# Doc Updater - 文档更新技能

## 触发条件

当用户请求创建或更新某个模块/系统的文档时执行此技能。

## 文档结构规范

每个系统文档应包含以下章节：

### 1. 系统定位

简要说明系统的核心职责和定位（1-2句话）。

### 2. 系统意义

列出系统的核心价值（3-5个要点）。

### 3. 文件结构

| 文件 | 路径 | 职责 |
|------|------|------|

### 4. 核心数据结构

使用Lua类型注解格式：
```lua
---@class ClassName
---@field Field1 type 描述
---@field Field2 type 描述
```

### 5. 核心类与接口

每个核心类应包含：
- 类定义（含字段说明）
- 主要接口列表

### 6. 配置表格式（如适用）

说明配置文件的格式和字段含义。

### 7. 执行流程（如适用）

说明核心流程步骤。

### 8. 使用示例

提供简洁的代码示例。

## 文档目录结构

```
d:\Workspace\Document\PrevailDocus\
└── Modules\
    └── [系统名]\
        └── [系统名]文档.md
```

## 执行步骤

### Step 1: 收集信息

根据用户输入，确定：
- 系统/模块名称
- 相关源文件路径
- 配置表路径
- 其他说明

### Step 2: 分析代码

1. 读取相关源文件，提取：
   - 类定义和字段
   - 核心函数和接口
   - 模块间的依赖关系

2. 读取配置表（如有），提取：
   - 配置字段含义
   - 数据格式规范

### Step 3: 编写文档

按照上述文档结构规范，编写精炼的文档内容：

- **定位**：1-2句话概括系统核心职责
- **意义**：3-5个核心价值点
- **文件结构**：表格形式，清晰标注职责
- **数据结构**：使用Lua类型注解，字段说明简洁
- **接口**：列出公开接口，说明参数和返回值
- **配置表**：给出格式示例和字段说明
- **流程**：关键流程步骤清晰
- **示例**：最小可运行示例

### Step 4: 输出文档

1. 确定文档保存路径：`Modules/[系统名]/[系统名]文档.md`
2. 如果目录不存在，创建目录
3. 写入文档内容
4. 确认文件已保存

## 文档质量标准

- **精炼**：避免冗余，每个词都要有意义
- **准确**：字段类型、返回值必须与代码一致
- **完整**：覆盖定位、意义、文件、结构、接口、字段等要素
- **可操作**：示例代码必须可运行

## 注意事项

1. 文档语言与代码保持一致（中文注释用中文，英文用英文）
2. 类型注解使用LuaDoc格式
3. 表格字段说明要简洁，避免重复"表示"、"用于"等词
4. 接口说明只列出公开接口，不列出私有方法
5. 配置表字段按实际用途命名，不要照抄原配置键名
