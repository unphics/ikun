# Code Reviewer - 代码审查技能

## 触发条件

当用户请求代码审查时，自动执行此技能。

## 审查优先级

### 第一优先级：逻辑错误

检查以下方面：

1. **边界条件处理**
   - 空值检查是否完整
   - 数组索引是否越界
   - 数值运算是否溢出

2. **状态一致性**
   - 状态转换是否完整
   - 并发访问是否安全
   - 资源释放是否正确

3. **业务逻辑正确性**
   - 条件判断是否符合预期
   - 循环终止条件是否正确
   - 递归终止条件是否存在

4. **返回值与错误处理**
   - 错误是否被正确传播
   - 默认值是否合理
   - 异常情况是否被处理

### 第二优先级：模块拆分

1. **职责单一性**
   - 每个模块是否只负责一件事
   - 是否存在上帝类/上帝函数
   - 公共逻辑是否被正确抽取

2. **耦合度**
   - 模块间依赖是否清晰
   - 是否存在循环依赖
   - 跨模块调用是否合理

3. **接口设计**
   - 接口是否清晰稳定
   - 参数是否必要
   - 返回值是否明确

### 第三优先级：语义表达

1. **命名规范**
   - 变量/函数命名是否自解释
   - 是否遵循项目命名约定
   - 是否存在误导性命名

2. **注释质量**
   - 复杂逻辑是否有解释
   - 注释是否与代码一致
   - 是否存在无用注释

3. **代码格式**
   - 缩进是否一致
   - 空行是否合理
   - 模块长度是否适中

## 审查流程

### Step 1: 确定代码所属系统

根据代码路径确定所属系统，查找对应文档：

```
d:\Workspace\Document\PrevailDocus\
```

系统文档包括：
- 系统文档.md - 系统总览
- Modules/[系统名]/[系统名]文档.md - 各系统详细文档

### Step 2: 读取系统文档

理解系统设计：
- 系统定位与职责
- 核心数据结构
- 模块划分
- 接口规范

### Step 3: 执行代码审查

按优先级逐项检查代码，参考系统文档验证：
- 代码实现是否符合系统设计
- 数据结构使用是否正确
- 接口调用是否规范

### Step 4: 输出审查报告

## 输出格式

```markdown
# 代码审查报告

## 基本信息
- **文件**: [文件路径]
- **系统**: [所属系统]
- **审查时间**: [时间]

## 审查结果

### 逻辑错误
| 严重程度 | 位置 | 问题描述 | 建议修复 |
|---------|------|---------|---------|
| 🔴严重 | 行X | 描述 | 建议 |

### 模块拆分
| 严重程度 | 位置 | 问题描述 | 建议 |
|---------|------|---------|------|
| 🟡中等 | 行X | 描述 | 建议 |

### 语义表达
| 严重程度 | 位置 | 问题描述 | 建议 |
|---------|------|---------|------|
| 🟢建议 | 行X | 描述 | 建议 |

## 总结
[总体评价]
```

## 严重程度定义

- **🔴严重**: 会导致运行时错误、数据损坏或功能完全不可用
- **🟡中等**: 可能导致潜在bug、性能问题或维护困难
- **🟢建议**: 代码风格、优化建议、防御性编程增强

## 审查示例

### 示例：技能系统代码审查

**文件**: `Content/Script/System/Skill/SkillController.lua`

**系统文档**: `Modules/技能系统/技能系统文档.md`

**审查要点**：

1. 逻辑错误检查
   - `IsSkillRunning` 的状态判断是否正确
   - `CancelRunningSkill` 是否正确清理所有状态
   - 技能实例列表的增删操作是否线程安全

2. 模块拆分检查
   - SkillController 是否承担了过多职责
   - 技能实例管理是否应该独立成类

3. 语义表达检查
   - 函数命名是否清晰表达意图
   - 关键逻辑是否有注释说明

## 注意事项

1. 审查时应先阅读系统文档，确保理解系统设计意图
2. 逻辑错误是最重要的审查点，必须优先检查
3. 对于系统特定的最佳实践，应参考系统文档中的约定
4. 审查结果应具体、可操作，避免模糊表述
5. 保持审查客观公正，以提升代码质量为目的
